## Находки (кандидаты в дефекты / IMPL_DEBT)

1. **Нет защитного пола цены в `rpc_lower_price`** (E2E-TSP-03): клэмп только до 1 ₸/кг; таблица `minimum_prices` пуста, `rpc_get_minimum_price` адаптером не вызывается. Канон MS4-BT-11/D-M6-3 нарушен. В IMPL_DEBT не зарегистрировано → завести строку долга.
2. **Underfill-исходы отсутствуют в адаптере** (E2E-TSP-04): `rpc_self_close_due_pools` лишь флипает статус пула (`filled`/`closed`); партии/аллокации зависают `matched` на закрытом пуле (deal не обнуляется, на рынок не возвращаются, контакт не раскрывается при filled≥30%). Канон-RPC `rpc_pool_accept_partial`/`rpc_pool_return_batches` недостижимы (нужен `awaiting_mpk_decision`). Частично покрыто TSP-ADAPTER-01 (CONVERGENCE pending), но конкретный batch-stranding gap не зарегистрирован → отдельная строка долга.
3. **Deadlock на конкурентных accept** (E2E-TSP-07): `rpc_self_accept_offer` двух МПК на один батч → у проигравшего `40P01` вместо бизнес-ошибки; нет SKIP LOCKED / единого порядка блокировок (offer → batch → pool_line/pool). Целостность ок (одна аллокация, один инкремент), но клиенту отдаётся ретраебельный 500-класс.
4. **`fn_tsp_resolve_sku` даёт grade S для явного VS-профиля**: бычок Ангус (elite_meat) 18 мес / 450 кг попал в SKU `TSP-0003`, но `batches.grade_standard_id` = S (a0293120), хотя grade_id этого SKU = VS. Расхождение grade_standard_id ↔ tsp_skus.grade_id на деплое — проверить задеплоенную версию `rpc_create_batch`/скоринга (наблюдение, на матчинг внутри прогона не влияло — матч идёт по `grade_standard_id`).
5. **OTP TTL хардкод в edge-функции** (`OTP_TTL_SECONDS=300`, `MAX_ATTEMPTS=3` в `supabase/functions/bird-otp/index.ts`) — standards-as-data (P8) не соблюдён; конфиг-таблицы для OTP нет.
