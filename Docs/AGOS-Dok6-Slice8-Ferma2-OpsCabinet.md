## 0. Дизайн-рамка

**Язык — язык shell, без изобретений.** Каркас `IonShellFrame` + `TabHead` (заголовок «Ферма»;
Topbar-принцип admin-зоны к shell НЕ применяется — прецедент `FarmScreen.tsx:5`). Верхние табы —
тот же паттерн `.mk-tabs`, что в Рынке (`MarketScreen.tsx:123`): текстовые сегменты, без иконок.
Иконки контента — только Phosphor через `PhIcon` (weight по канону блока). Шрифт Geist;
**mono (`mk-mono`, tabular-nums) — только цифры/даты/номера бирок** (R-типографика: mono на
русской фразе = дефект). Хиты ≥44px; primary-кнопка отметки обхода ≥48px.

**Статус всегда = точка 5px + текст, без цветных заливок** (handoff §2.7/§11): зелёный — факт
«ок» с данными; янтарный — окно/внимание/нет данных; красный — просрочка/угроза. Красный текст —
только на данных («2 просрочены»), не на декоре. Единственная разрешённая заливка-диапазон —
янтарная подложка дней окна в календаре Месяца (§3.3).

**Хедер платформы и нижний таб-бар кабинета НЕ трогаем** (handoff §0). Всё живёт внутри
таба «Ферма» нижней навигации кабинета.

```

└─ .mk-tabs: Обзор (дефолт) · Задачи · Стадо · Ещё        ← state + deep-link (§1.1)

   │            └─ карточка животного → SHEET-AN            (F9)
```

### 1.1 Меж-табовые переходы (контракт deep-link)

Зоны и строки ведут в конкретный таб+состояние; F4 обязан дать внутренний навигационный
вызов вида `goFarmTab(tab, params)` (реализация — по месту, паттерн внутримодульной навигации
Рынка): `{tab:'tasks', horizon:'week'|'month'|'year', day?, taskId?}` ·
`{tab:'herd', mode?:'walk', animalId?}`. Все переходы карты навигации handoff §3 выражаются
этим вызовом.

## 2. SCR-OV · «Обзор» (F5, ARS-281)

**Job:** «за 30 секунд: иду по плану — или что сегодня первым делом». Не дашборд KPI.
Данные: **один вызов `rpc_get_farm_overview`** (slice §2.7) — офлайн-кэш-юнит целиком.
Подзаголовок под TabHead при офлайне/старом кэше: `данные на HH:MM` (из `fetched_at`, D145).

Порядок блоков (ничего между ними не вставлять):

### 2.1 Четыре зоны контроля — сетка 2×2, карточки-кнопки

Анатомия карточки: заголовок-капс → крупное значение (`mk-mono`, tabular-nums) → строка
статуса (точка + текст) → шеврон. Тап по всей карточке:

| Зона | Значение | Статус-строка (состояния) | Тап → |
|---|---|---|---|
| **Стадо** | `herd.total` голов | обход отмечен → зелёная точка «обход HH:MM · все группы»; НЕ отмечен → янтарная «обход не отмечен — нет данных» (ЗЕЛЁНОГО без данных НЕ бывает) | `walkthrough_marked ? {tab:'herd'} : {tab:'herd', mode:'walk'}` |
| **Цикл** | фаза + «день N/M» + тонкий прогресс-бар | ближайшее окно: «окно ИРТ/ПГ-3 · осталось K дн»; K ≤ 2 → «горит» янтарным/красным | `{tab:'tasks', horizon:'year'}` |
| **Задачи сегодня** | `today_done/today_total` | `overdue > 0` → «K просрочены» красным; иначе «по плану» | `{tab:'tasks', horizon:'week'}` |
| **Ресурсы · корма** | `min_days_left` дн | сигналы по позициям: «сено — закупить · к/корм 23 дн»; `tracked=false` → «не ведётся» + вход в настройку (F12) — никаких выдуманных цифр | F12-экран или state «не ведётся» |

Дни запаса показываются в **днях**, не в кг (формула — slice §7, D143).

### 2.2 «Требует внимания»

- Заголовок + красный счётчик. Сортировка приходит с сервера (`attention[].priority`,
  handoff §2.6: угроза животному → окно → просрочка → ресурсы) — UI НЕ пересортировывает.
- Строка: красная точка · заголовок (номера животных `mk-mono` внутри русской фразы) ·
  подстрока (причина/срок) · **кнопка-действие справа** (1 тап):

| `action.type` | Кнопка | Вызов |
|---|---|---|
| `inspect` | «Осмотр» | `rpc_create_farm_task` (slice §2.14, `p_animal_event_id`) → toast «Задача на сегодня» |
| `open_animal` | «Открыть» | SHEET-AN (`animalId`) |
| `open_window` | «К окну» | `{tab:'tasks', horizon:'month'}` (фокус окна) |
| `to_vet` | «Ветврачу» | confirm-лист → `rpc_create_vet_case_from_event` (slice §2.6) → строка меняет кнопку на бейдж «кейс открыт» |
| `reschedule_today` | «На сегодня» | `rpc_reschedule_farm_task` (slice §2.10) |

- Пусто → явная позитивная строка: зелёная точка + «Отклонений нет — техкарта идёт по плану».
  Блок НЕ скрывается молча.

### 2.3 «Сегодня — ближайшие»

3 ближайшие невыполненные задачи + строка «Ещё N задач — до вечера» → `{tab:'tasks',
horizon:'week'}`. Анатомия строки задачи (общая для Обзора и Недели, handoff §4.3):
чекбокс (зона тапа — вся левая колонка 48px) · название · метаданные (чип СОП-кода ·
поголовье · инициал исполнителя; задача из окна → «окно до 14 июля» янтарным; из отклонения →
красная точка + «по отклонению») · время `mk-mono` (`due_time`, если есть).

Отметка чекбокса: `rpc_complete_farm_task` → название серое + line-through, зона «Задачи
сегодня» пересчитывается **мгновенно** (оптимистично, до ответа сервера — общий факт с
табом «Задачи», slice §6). Это ЕДИНСТВЕННЫЙ ввод на Обзоре (handoff §2.4).

### 2.4 Состояния экрана

| State | Условие | Рендер |
|---|---|---|
| A норм | план active, есть данные | §2.1–2.3 |
| B офлайн | нет сети / кэш | всё из кэша + «данные на HH:MM»; действия уходят в outbox (D145) |
| C обход не внесён | `walkthrough_marked=false` | зона «Стадо» янтарная «нет данных» — до отметки; назавтра снова |
| D плана нет | `cycle.no_plan=true` | зона «Цикл»: «плана нет»; `draft_plan_id` есть → CTA «Активировать план» (confirm → `rpc_activate_production_plan`); нет → CTA «Настроить план» → мастер/resume. Остальные зоны живут (обход/стадо работают без плана) |
| E профиль пуст | нет стада вовсе | SCR-F0a хук (см. §1.2) вместо зон |
| F всё штатно | нет attention | явная строка «по плану» (§2.2 пусто) — не пустота |

## 3. SCR-TA · «Задачи» (F6/F7/F8)

Один экран, сегмент-контрол **Неделя | Месяц | Год** под заголовком таба. Подзаголовок —
контекст цикла: «Цикл 2026 · Случка — день 18/60» (`context` из RPC). Кнопка «+» (в ряду
сегмент-контрола, справа) — ручная задача: лист с полями название · дата (деф. сегодня) ·
время (опц.) · исполнитель (опц.) → `rpc_create_farm_task` (slice §2.14).
Данные: `rpc_get_tasks_horizon(horizon, anchor)` — кэш-юнит на горизонт (slice §2.8).

### 3.1 Неделя (исполнение) — F6, ARS-282

Сверху вниз, порядок жёсткий:

1. **Закреплённый блок «горит»** (`burning[]`) — просрочки и закрывающиеся окна. Первый блок,
   пролистать нельзя. Строка: точка (красная просрочка / янтарное окно) · название · подстрока
   («план был 10 июля · 8 голов» / «осталось 2 дня · 24 головы») · действие:
   просрочка → «На сегодня» (`rpc_reschedule_farm_task`); окно → «Сегодня 10:00» = переход к
   задаче дня. Перенос НЕ двигает окно (slice D141/§2.10) — копирайт подтверждения не обещает обратного.
2. **Полоса недели** — 7 дней: день недели, число, точки-нагрузка (1 точка ≈ 1–2 задачи,
   максимум 4), красная точка = есть просрочка того дня. Сегодня — залит тёмным. Тап по дню →
   план этого дня (ниже).
3. **План дня** — заголовок «Вс, 12 июля» + счётчик «8 задач · N ✓»; строки задач (анатомия
   §2.3), у каждой виден исполнитель (аватар-инициал). Выполненные раньше по дню — свёрнутая
   строка «Выполнено утром — N задач» (тап раскрывает).

Отметка задачи синхронно обновляет счётчики Недели и зону «Задачи» Обзора (общий факт, slice §6).
**Пустая неделя (межфазье):** не пустота — строка следующей вехи: «Впереди: Пт 17 — открывается
окно ИРТ/ПГ-3» (из `milestones` месяца).

### 3.2 Месяц (подготовка) — F7, ARS-283

1. **Календарная сетка месяца:** окна — **диапазоны** (янтарная заливка всех дней окна, включая
   вет-окна из `vaccination_plan_items` — merge по датам, D75), точки-нагрузка, красная точка —
   просрочка, сегодня залит, прошедшие дни приглушены. Легенда под сеткой (окно · нагрузка ·
   просрочка). Пагинация ‹ › по месяцам (`p_anchor`).
2. **«Подготовиться к окнам»** (`prep[]`): чекбокс · название («Купить вакцину ИРТ/ПГ-3 —
   24 дозы») · «до старта окна · дедлайн 17 июля» (дедлайн = старт окна, D141) · остаток дней
   `mk-mono`. Чек — тот же `rpc_complete_farm_task`.
3. **«Вехи месяца»** (`milestones[]`, derived D146): дата/диапазон `mk-mono` («до 14», «17–24») ·
   точка статуса · название с поголовьем → тап в окно/задачу.

### 3.3 Год (настройка) — F8, ARS-284

1. Заголовок «Цикл 2026 — целиком» + диапазон («июн 26 → окт 27»).
2. **Вертикальный таймлайн фаз** (`phases[]`, reuse-читатель ARS-215): пройденная — галка;
   **активная — акцентная точка + карточка**: название, «день 18/60», прогресс-бар, ближайшие
   вехи фазы (дата + название); будущие — контурные точки, название + диапазон + аннотация
   («ожидается ~40 отёлов»).
3. **Единственная ручная правка** — строка в карточке активной фазы случки:
   «Старт случки — 24 июня · изменить» (иконка карандаша, приписка «пересчитает все окна»).
   Флоу: тап → date-picker → **превью** (`fn_preview_cascade`, список «фаза: было → станет») →
   confirm «Пересчитает все будущие окна и вехи. Прошлое не изменится.» →
   `rpc_shift_breeding_start` (slice §2.9) → toast + refetch всех горизонтов и Обзора.
   Отмена на любом шаге без следов.

## 4. SCR-WK · «Обход» (режим таба «Стадо») — F9, ARS-285

**Job:** «зафиксировать неладное за секунды, не останавливая обход». Вход: «Стадо» → карточка
обхода, или зона «Стадо» Обзора при неотмеченном обходе. Данные: `rpc_get_herd_board`
(slice §2.4). **Экран полноценно работает офлайн** (все мутации — в outbox, D145).

Сверху вниз:

1. Заголовок + дата/время суток + **индикатор офлайна**: перечёркнутый wifi + «офлайн —
   запишется». Подсказка: «По умолчанию все 86 в порядке. Вводите только отклонения».
2. **Блок отметки обхода** — два состояния:
   - не отмечен: янтарная точка «Обход не отмечен» · справа «зона „Стадо“ — нет данных» ·
     большая primary-кнопка **«Обход сделан»** (≥48px) → `rpc_mark_walkthrough` (локальная дата!);
   - отмечен: зелёная галка «Обход сделан · 06:40» · «факт ушёл в „Обзор“, зона „Стадо“
     обновлена». Повторный тап невозможен (кнопки нет). Назавтра — снова «не отмечен» (чистая
     функция от даты, slice §1.4).
3. **«Отклонения с обхода»** — счётчик за сегодня; пусто → dashed-плейсхолдер «Пока ничего —
   это хорошо»; строки — анатомия §2.2 + кнопка действия («Осмотр» / «Ветврачу»).
4. **«+ Отклонение» — ровно 2 шага** (инлайн-визард в потоке экрана, НЕ отдельный экран):
   - **Шаг 1 из 2 — кто?** чипы номеров (`animals_recent` группы, `mk-mono`, ≥44px) +
     поле «поиск №…» (ввод нового номера легален — реестр lazy, D140); «Отмена»;
   - **Шаг 2 из 2 — что с №N?** чипы словаря `animal_event_types` (active, по sort_order):
     `лежит · хромает · не ест · травма · признаки охоты · другое`;
   - выбор типа **завершает ввод**: `rpc_log_animal_event` (client_event_id из outbox) →
     строка в списке за сегодня + «Требует внимания» Обзора + событие в карточке животного;
     после — необязательное «добавить заметку/фото» (не блокирует) и предложение действия
     (Осмотр / Ветврачу — те же вызовы §2.2).
5. Футнот: «Поимённый чек — только в расколе (вакцинация, взвешивание) и при инвентаризации»
   (режимы 2–3 — след. скоуп; UI-заглушек НЕ рисуем).

## 5. SCR-HD · таб «Стадо» + SHEET-AN (F9, ARS-285)

- **Карточка обхода** (первый блок): состояние отметки (как §4.2 кратко) + CTA «Обход» →
  SCR-WK. Если обход не отмечен — карточка янтарная (та же семантика, что зона Обзора).
- **Группы** (`groups[]`): строка = категория · `head_count` голов `mk-mono` · ср. вес.
  Тап → существующие экраны групп (скоуп ARS-171 — CRUD не переопределяем, HS-2).
- **Открытые события** (`open_events[]`): строки §2.2 с номером бирки → SHEET-AN.
- **SHEET-AN · карточка животного** (`rpc_get_animal_card`): шапка «№41» `mk-mono` + группа +
  статус (в стаде / выбыло) · история событий (тип, дата, кто, статус open/closed, линк
  vet-кейса) · действия: «+ Отклонение» (визард §4.4 с предвыбранным животным) · «Закрыть
  событие» на открытых (`rpc_close_animal_event`, confirm). Выбывшее животное: серый бейдж,
  история читается, действия скрыты (handoff §9.6).

## 7. Живые связи (UI-уровень; контракт данных — slice §6)

| Действие | Немедленный локальный эффект | Инвалидация кэш-юнитов |
|---|---|---|
| «Обход сделан» | блок §4.2 → зелёный; зона «Стадо» Обзора янтарная → зелёная | overview, herd_board |
| Добавлено отклонение | +1 счётчик §4.3; строка появляется без ожидания сети (optimistic из outbox) | overview, herd_board, animal_card |
| Отметка задачи | line-through + счётчики везде синхронно | overview, horizon(week/month) |
| «На сегодня» | задача в плане дня; окно не двигается | horizon(week), overview |
| Сдвиг старта случки | после confirm — полный refetch | ВСЕ юниты модуля |
| «Ветврачу» | кнопка строки → бейдж «кейс открыт» | overview, herd_board, animal_card |
| Новые сутки | зона «Стадо» и блок обхода → «не отмечен» (рендер от даты, кэш не трогается) | — |

Optimistic-правило: локальный эффект рисуется сразу; откат только при доменном отказе
(`{ok:false}`) с видимым «не записалось» (slice §8) — тихих откатов нет.

## 8. Критерии приёмки (handoff §10 → SCR)

- **SCR-OV:** ≤30 сек и без скролла видны: число+суть отклонений, ближайшее окно с остатком
  дней, статус задач дня, дни запаса. Из любой строки внимания — действие в 1 тап.
- **SCR-TA:** с любого горизонта ≤2 тапа до конкретной задачи дня; окно ВЕЗДЕ — диапазон с
  остатком дней; смена старта случки меняет все будущие даты (и только их).
- **SCR-WK:** отклонение ≤2 действий, офлайн; отметка обхода мгновенно меняет зону «Стадо».
- **Офлайн:** все экраны открываются из кэша с меткой времени; очередь переживает перезапуск.
