# ЧАСТЬ A — Главная фермера

## A0. Идея экрана

Экран построен на **модели внимания из трёх ярусов** (не «дашборд с цифрами»):

1. **ТРЕБУЕТ РЕШЕНИЯ** — процесс остановлен, ждёт выбора/ответа фермера.
2. **ИДЁТ САМО** — процесс движется без участия фермера, просто наблюдение.
3. **БЫСТРЫЙ ДОСТУП** — якорь: ферма и ближайшие события.

**Правило видимости (механика):** ярусы 1 и 2 **скрываются целиком, когда пусты**.
Ярус 3 и грид сервисов присутствуют **всегда** — грид «якорь», не должен прыгать.

## A1. Шапка (постоянна, не скроллится вместе с ярусами)

Три элемента в одну строку:

- **Строка «Спросить…»** — единственный вход в AI-ассистента. Тап → AI (контекст
  `home`). Отдельная кнопка микрофона → AI в голосовом режиме.
- **Ценовой стикер** — справочная цена ведущей товарной группы стада: короткое имя
  категории, `₸/кг`, стрелка тренда (▲/▼/—). Тап → шторка справочных цен.
  ⚠️ см. Флаг F-1 (видимость не-членам + антитраст-дисклеймер).
- **Аватар хозяйства** (инициалы) → Кабинет. **Янтарная точка** на аватаре = в
  Кабинете есть требующее внимания действие.

## A2. Баннер «Актуальное» (карусель)

- Карусель **≤ 3 карточек**, авто-смена каждые 6 сек, точки-переключатели.
  **Никогда не пустует** (иначе грид под ним прыгает) — фикс-высота.
- Карточка: кикер (мелкий лейбл) + заголовок + строка действия. Тап → соответствующее
  действие.
- **Какой набор карточек показывать (механика):** зависит от статуса членства.
  - не член (`none`) / прекращено (`terminated`) → набор **join**: первая карточка
    «Вступите в TURAN — продажа партий, цены, защита сделок» → подать заявку.
  - иначе → набор **season**: курс TURAN, Platform Pro, справочные цены.
- Возможные действия карточек: открыть курс · подключить Pro · открыть справочные
  цены · подать заявку на членство.

## A3. Грид сервисов (ЯКОРЬ — присутствует всегда)

- Плитки сервисов. Текущий набор: **Рынок скота** (только для членов), **Специалисты**,
  **Рег. животных** (помечен «скоро», неактивен), **Все сервисы**.
- «Маркет/Рынок» имеет **отдельный таб** — в понимании навигации не дублируется, в
  гриде это вход в тот же раздел.
- Механика:
  - плитка «скоро» — неактивна, с бейджем «скоро».
  - плитка «только для членов» (Рынок скота) при отсутствии членства → гейт членства
    (см. ТЗ по членству, S1), не прямой вход.

## A4. Ярус 1 «ТРЕБУЕТ РЕШЕНИЯ»

- Заголовок с янтарной точкой + счётчик.
- Карточки — **контентные** (не счётчик): источник + срок, заголовок, опц. пояснение,
  **1–2 кнопки действия** (основная/вторичная).
- Показывается **максимум 3**; если больше — в заголовке ссылка «ещё N →» (ведёт в
  раздел сообщений/список).
- Сортировка по приоритету (меньше число = выше).
- **Источники карточек (что сюда попадает):**
  - **Продажа:** партия в состоянии «решение» — покупатели не согласились по цене →
    действия «Снизить до X ₸/кг» / «Другие варианты».
  - **Продажа · сделка:** партия подтверждена → «Отметьте отгрузку» → «Отгружена» /
    «Открыть».
  - **Членство TURAN:** одобрено→оплатить взнос; истекает→продлить; grace→оплатить;
    истекло→оплатить; отклонено→подать заново; прекращено→подать заявку.
    (Полные копи и сроки — в ТЗ по членству.)

## A5. Ярус 2 «ИДЁТ САМО»

- Заголовок с серой точкой + счётчик.
- Элементы — **без кнопок** (тап открывает деталь). Цветная точка-статус + заголовок
  + подстрока-статус + источник.
- Максимум 3; если больше — «все партии →» (в список партий).
- Сортировка по близости события.
- **Что сюда попадает:** партии в состояниях offering (ждёт ответа) / matched
  (покупатель найден) / published (в продаже) / dispatched (в пути) / scheduled
  (выйдет в продажу) / delivered без оценки. Плюс членство `pending` → «Заявка на
  рассмотрении · ответ в течение N рабочих дней».

## A6. Ярус 3 «БЫСТРЫЙ ДОСТУП» (присутствует всегда)

- **Кнопка «Ферма»** с динамической подстрокой из сводки стада:
  - есть стадо: «Ферма · N голов · M групп · K задач сегодня» (+ «есть просрочка»).
  - стадо пустое: «Ферма · стадо не заполнено».
  - иначе цикл: «Ферма · <фаза>, день <n> · задачи».
  - Тап → экран Фермы.
- **Блок «Впереди»** — горизонт ближайших событий хозяйства (название + даты).
  Показывается **только в «тихом» состоянии** (см. A7).

## A7. Состояния экрана (states)

| Состояние | Условие | Что показывается |
|---|---|---|
| **Загрузка** | данные грузятся | скелетон (плейсхолдеры блоков) |
| **Тихо (quiet)** | нет карточек «решения» и ≤1 «идёт само» | ярусы 1/2 скрыты; в ярусе 3 показывается «Впереди» |
| **Рабочее** | есть решения/наблюдения | ярусы 1/2 наполнены, «Впереди» скрыт |
| **Не член** | membership none/terminated | баннер-набор «join»; Рынок в гриде → гейт |
| **Стадо не заполнено** | новая ферма | подстрока «Ферма · стадо не заполнено» |
| **Офлайн** | нет сети | данные из кеша; pull-to-refresh не обновляет (без падения) |

- **Pull-to-refresh** доступен на всём экране (обновляет сводку, партии, статусы).
- Ярлык экрана в заголовке фрейма несёт текущий статус членства (тех. индикатор).

## A8. Источники данных (для программиста)

- Статус членства (`MembershipStatus`).
- Сводка фермы — `rpc_get_farm_summary` (голов, групп, задачи, план «впереди»);
  для демо/анонима — сид.
- Партии (`batches`) — питают ярусы 1 и 2.
- Справочные цены — стикер и шторка цен.

# ЧАСТЬ B — Главная МПК

## B0. Идея экрана

У МПК Главная — **не ярусная модель фермера**, а «профиль + два гейта допуска +
доступ к закупкам». Логика: закупки (TSP) открываются только когда пройдены **два
независимых одобрения**.

## B1. Герой

- Иконка, **название организации**, строка «регион · БИН <бин>».
- Три показателя: **активных** (пулы в наборе/приёмке) · **набрано, т** (тоннаж по
  пулам в приёмке) · **сделок/мес** (завершённые пулы). ⚠️ см. Флаг F-3.

## B2. Баннер «Тип организации» (первый гейт)

Подтверждение, что организация действительно МПК (тип `mpk` требует одобрения, канон
D-IDM-7):
- **на проверке:** «Проверяем тип организации · 2–5 рабочих дней».
- **подтверждён:** «✓ Тип МПК подтверждён».
- **отклонён:** «✗ Тип организации не подтверждён» + причина + «Обратиться в TURAN».

## B3. Баннер «Членство TURAN» (второй гейт)

- **на рассмотрении:** «Членство в TURAN на рассмотрении · 1–3 рабочих дня» + действие
  активации.
- **активно / grace:** «✓ Членство TURAN активно».

## B4. Доступ к закупкам (TSP) — замок / вход

- **Механика допуска:** закупки открыты **только если** тип = подтверждён **И**
  членство = активно/grace. Оба условия обязательны.
- **Закрыто (замок):** «🔒 Доступ к закупкам · доступен после подтверждения типа и
  активации членства».
- **Открыто:**
  - действие «Открыть закупки» (в раздел TSP);
  - «Входящие офферы · N» (поставщики прислали предложения — ответить) / «Пока нет
    новых предложений»;
  - до 2 недавних пулов: заголовок + «X/Y гол» + чип статуса (Набирается / Набран /
    Приёмка / Истёк / Закрыт / Завершён).

## B5. «Первые шаги» (только пока доступа нет)

Чек-лист онбординга, показывается **только пока закупки закрыты**: заполнить профиль
компании · дождаться подтверждения типа МПК · пригласить команду.

## B6. Состояния экрана (states)

| Ось | Значения |
|---|---|
| Тип организации | на проверке / подтверждён / отклонён (+причина) |
| Членство | на рассмотрении / активно / grace |
| Доступ к TSP | закрыт (замок + «первые шаги») / открыт (закупки + офферы + пулы) |
| Входящие офферы | 0 / N |
| Пулы | пусто / список с чипами статусов |

- **Pull-to-refresh** доступен (поллинг статусов типа/членства/пулов).

## B7. Ключевые отличия Главной МПК от Главной фермера

| | Ферма | МПК |
|---|---|---|
| Модель | 3 яруса внимания | профиль + гейты + TSP |
| AI-строка «Спросить» | есть (в шапке) | нет |
| Ценовой стикер | есть | нет |
| Гейт доступа | членство | тип **И** членство (два независимых) |
| Основной объект | партии/стадо | пулы закупок/офферы |
