## A. Подтверждённые находки — critical/verified (9)

Полная детализация (все — категории layout-stability; именно они прошли адверсариальную верификацию).

### A1. iOS: весь верх кабинета уходит под статус-бар/чёлку — нигде нет safe-area-inset-top
**Приоритет:** critical · **Категория:** layout-stability · **Причина:** implementation
- **Экран:** вся оболочка (все экраны /cabinet, визарды, MPK-модалы)
- **Место:** `src/pages/cabinet/shell/shell-proto.css:154`
- **Что не так:** Пользователь iPhone видит заголовок «Рынок», ask-бар Главной, кнопку «‹ назад» и OfflineBar наполовину перекрытыми часами/чёлкой — приложение выглядит сломанным на каждом экране. Техпричина: в кабинете ни одно правило не использует env(safe-area-inset-top) (grep по src подтверждает: top-inset есть только в auth-фаннеле и BootScreen). Все шапки — sticky top:0 (.tab-head shell-proto.css:153-158, .hh-row :14-15, .sub-head :165-166, .thr-head messages-proto.css:39-40, .mk-wiz-bar визардов), OfflineBar — первый элемент IonPage (IonShellFrame.tsx:29). При этом StatusBar.setOverlaysWebView({overlay:false}) вызывается ТОЛЬКО на Android (CapacitorHost.ts:99-102) — на iOS этот API не существует, WKWebView всегда фуллскрин под чёлкой. IonHeader/IonToolbar (которые сами берут --ion-safe-area-top) не используются.
- **Как чинить:** В ionic.css добавить общее правило: `.agos-cabinet-stage .ion-page { padding-top: env(safe-area-inset-top, 0px); }` (на Android c overlaysWebView:false env()=0 — no-op, регрессии нет) и то же для фуллскрин-модалов: `ion-modal.agos-mpk-modal .mpk-modal { padding-top: env(safe-area-inset-top, 0px) }`. Sticky-шапки остаются top:0 внутри отпаддингованной страницы и работают корректно.
- **Нативный риск:** Проявляется ТОЛЬКО в Capacitor-сборке на iOS (и в iOS PWA standalone): в браузере/десктопе env()=0 и дефект невидим — поэтому он не пойман до сих пор. Без фикса каждый экран на любом iPhone с чёлкой перекрыт системным статус-баром.

### A2. Все 7 шрифтов грузятся с Google Fonts CDN — в нативной сборке офлайн их нет вообще
**Приоритет:** critical · **Категория:** layout-stability · **Причина:** stack-config
- **Экран:** вся оболочка
- **Место:** `index.html:17`
- **Что не так:** Фермер в поле без сети запускает нативное приложение первый раз (или после чистки кеша WebView) — весь кабинет рендерится системным шрифтом вместо Geist/Geist Mono: типографика канона (D-UI-FARMER-RULES-01) исчезает целиком. Даже с сетью display=swap даёт FOUT: заголовки с letter-spacing -0.02em сначала рисуются fallback-шрифтом, потом перескакивают — видимый сдвиг строк на каждом холодном старте. Техпричина: index.html:13-17 — единственный источник шрифтов это <link href="https://fonts.googleapis.com/css2?family=Geist...">; в dist ни один woff2 не попадает, capacitor webDir=dist подхватывает только этот тег.
- **Как чинить:** Самохостить используемые семейства: добавить @fontsource-variable/geist (+geist-mono и остальные реально используемые) в package.json (с manual peer-tree-чеком по D-DEP-BUMP-01), импортировать в src/index.css вместо CDN-link, убрать строки 13-17 из index.html. Vite инлайнит woff2 в dist — шрифты доступны офлайн и без FOUT (font-display: fallback/optional).
- **Нативный риск:** В Capacitor-сборке офлайн-первый-запуск = навсегда системные шрифты до появления сети; сервисворкера нет, WKWebView-кеш CDN не гарантирован. Это прямое нарушение сценария «офлайн в поле».

### A3. Landscape не залочен в нативных проектах — портретная 440px-колонка разваливается при повороте
**Приоритет:** important · **Категория:** layout-stability · **Причина:** stack-config
- **Экран:** вся оболочка
- **Место:** `ios/App/App/Info.plist:36`
- **Что не так:** Фермер кладёт телефон горизонтально (например, смотрит видео до этого) — кабинет превращается в узкую колонку 440px по центру с мёртвыми кремовыми полями по бокам, таб-бар шириной 440px висит в центре экрана, клавиатура съедает почти весь контент. Техпричина: UI жёстко портретный (.phone max-width:440px, cabinet.css:98-104), manifest.webmanifest залочен "orientation":"portrait" — но это действует только на PWA. Info.plist:33-38 разрешает UIInterfaceOrientationLandscapeLeft/Right для iPhone (дефолт шаблона Capacitor), AndroidManifest.xml:11 не задаёт android:screenOrientation (configChanges c orientation = свободное вращение).
- **Как чинить:** Info.plist: оставить в UISupportedInterfaceOrientations (iphone) только UIInterfaceOrientationPortrait. AndroidManifest.xml: добавить android:screenOrientation="userPortrait" в <activity> MainActivity. iPad-массив можно оставить как есть (App Store требует все ориентации для iPad-совместимых приложений, либо выставить UIRequiresFullScreen).
- **Нативный риск:** Дефект существует только в нативных сборках — PWA уже залочена манифестом. После фикса поведение iOS/Android совпадёт с PWA.

### A4. Чат-док (инпут Консультанта/тредов) сидит в зоне home-indicator — нет нижней safe-area
**Приоритет:** important · **Категория:** layout-stability · **Причина:** implementation
- **Экран:** ThreadScreen / ConsultantScreen
- **Место:** `src/pages/cabinet/shell/messages-chatscope.css:7`
- **Что не так:** На iPhone с жестовой полосой поле ввода чата и кнопка отправки/микрофона прижаты к самому низу экрана: подпись «Консультант отвечает по справочным данным TURAN» лежит прямо под системной полосой, тап по кнопке send конфликтует с жестом Home. Техпричина: на thread-роутах таб-бар скрыт (hideTabBar, CabinetApp.tsx:345), низ ion-content = низ экрана; единственный нижний отступ — `ion-content.ion-noscroll .phone-scroll { padding-bottom: 10px }` (messages-chatscope.css:7) без env(safe-area-inset-bottom). Для сравнения: .sh-foot (shell-proto.css:146) и таб-бар (:128) safe-area учитывают, чат-док — нет.
- **Как чинить:** messages-chatscope.css:7 — заменить `padding-bottom: 10px` на `padding-bottom: calc(10px + env(safe-area-inset-bottom, 0px))`.
- **Нативный риск:** В Capacitor на iPhone X+ инпут чата частично попадает под gesture-бар; случайные свайпы Home при отправке сообщений. На Android c жестовой навигацией — то же с системной полосой.

### A5. iOS авто-зум при фокусе: поля 13–15.5px + viewport без maximum-scale
**Приоритет:** important · **Категория:** layout-stability · **Причина:** stack-config
- **Экран:** Review, TURAN-обращение, MkSelect-поиск, чат, MPK-модалы, шторка цены
- **Место:** `index.html:6`
- **Что не так:** Фермер тапает в textarea отзыва или строку поиска породы — вся страница внезапно увеличивается (~120%) и после закрытия клавиатуры остаётся отзумленной/сдвинутой: классический web-артефакт, мгновенно убивающий ощущение нативности. Техпричина: viewport (index.html:6) не содержит maximum-scale/user-scalable (дефолтный шаблон Capacitor их ставит), а WKWebView зумит к полям с font-size <16px. Такие поля: .mk-input.area 14px (market-proto.css:48 — ReviewScreen.tsx:70, TuranScreen.tsx:79), .mk-input.mono 15px (:46), .mk-pick-search-in 15px (:79), chat-editor 15.5px (messages-chatscope.css:95), .mpk-input/.mpk-select 15px (cabinet.css:828,831), .finput 14px (cabinet.css:360-364), .rev-textarea 13px (cabinet.css:757).
- **Как чинить:** index.html:6 — привести viewport к капаситоровскому канону: `width=device-width, initial-scale=1.0, minimum-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover` (заодно отключает нецелевой pinch-zoom всего UI). Дополнительно (доступность) поднять фокусируемые поля до 16px: .mk-input.area, .mk-pick-search-in, chat-editor, .mpk-input.
- **Нативный риск:** Без фикса в iOS-сборке каждый фокус в перечисленных полях зумит layout; с maximum-scale=1 поведение станет идентичным нативному (Apple допускает это для WKWebView-приложений — это не Safari).

### A6. Скелет Главной не совпадает с реальной вёрсткой — контент прыгает при каждой загрузке
**Приоритет:** important · **Категория:** layout-stability · **Причина:** implementation
- **Экран:** HomeScreen
- **Место:** `src/pages/cabinet/shell/components/ScreenSkeleton.tsx:27`
- **Что не так:** На каждом холодном старте фермер видит, как после скелета плитки сервисов «вырастают», а весь контент ниже съезжает на ~50-60px — ощущение дешёвой веб-загрузки вместо нативного бесшовного перехода. Техпричина: скелет home (ScreenSkeleton.tsx:20-35) — баннер фикс 132px против реального .ban-tile aspect-ratio 1600/540 (~121px при 390px-экране, shell-proto.css:54), сервис-плитки h=64 против .svc min-height:88px (shell-proto.css:72), вертикальный gap 10px (.skel-wrap, cabinet.css:457) против .home-stack gap 22px + padding-top 14px (shell-proto.css:43).
- **Как чинить:** ScreenSkeleton.tsx variant 'home': баннер-блок сделать через aspect-ratio 1600/540 (style={{aspectRatio:'1600/540'}} вместо фикс h), плиткам h=88, обёртке — те же gap 22 и padding-top 14, что у .home-stack (или переиспользовать класс .home-stack для skel-wrap варианта home).

### A7. OfflineBar вставляется в поток и дёргает весь экран на ~30px при каждом обрыве сети
**Приоритет:** important · **Категория:** layout-stability · **Причина:** implementation
- **Экран:** вся оболочка
- **Место:** `src/pages/cabinet/shell/components/IonShellFrame.tsx:29`
- **Что не так:** В поле сеть мигает постоянно — при каждом offline/online весь контент экрана (шапка, карточки, то, что фермер сейчас читает) резко прыгает вниз и обратно вверх на высоту баннера: layout-нестабильность на самом частом полевом сценарии. Техпричина: OfflineBar (IonShellFrame.tsx:29) — обычный div ПЕРЕД IonContent внутри flex-колонки IonPage (.offline-bar, cabinet.css:202-205); появление/исчезновение меняет высоту ion-content без анимации.
- **Как чинить:** Сделать баннер оверлеем, не влияющим на поток: .offline-bar { position:absolute; top:0 (после фикса safe-area — top: env(safe-area-inset-top)); left:0; right:0; z-index:10 } внутри IonPage (position:relative уже есть у .ion-page), плюс transition по transform/opacity для мягкого появления. Контент перестаёт прыгать; читаемость шапки под баннером на 2-3 секунды офлайна приемлема (баннер полупрозрачным делать не нужно — он и так поверх sticky-шапки того же фона).
- **Нативный риск:** В Capacitor статус сети приходит от @capacitor/network (CapacitorHost.installNetwork) и переключается чаще, чем navigator.onLine в вебе — прыжки будут заметнее, чем в браузерной проверке.

### A8. Цвет статус-бара #fdf6ee не совпадает с фоном кабинета #f6f3ed (Android)
**Приоритет:** nice · **Категория:** layout-stability · **Причина:** implementation
- **Экран:** вся оболочка (Android)
- **Место:** `capacitor.config.ts:35`
- **Что не так:** На Android над приложением видна полоса статус-бара заметно более светлого/розоватого крема, чем фон кабинета — шов по верхней кромке на каждом экране, выдающий «обёрнутый сайт». Техпричина: StatusBar.backgroundColor '#fdf6ee' задан и в конфиге (capacitor.config.ts:35), и в рантайме (CapacitorHost.ts:100), и в theme-color (index.html:8) — а фактический фон оболочки --bg: #f6f3ed (cabinet.css:10, DS daylight). #fdf6ee — фон boot-пути/сплэша, не фон кабинета.
- **Как чинить:** Синхронизировать: в capacitor.config.ts:35 и CapacitorHost.ts:100 заменить '#fdf6ee' на '#f6f3ed' (фон кабинета, где пользователь проводит 99% времени). BootScreen/сплэш оставить #fdf6ee — переход бесшовный, т.к. в момент смены грузится контент. Зафиксировать пару токенов в Docs/AGOS-DesignRules-FarmerCabinet.md.
- **Нативный риск:** Чисто нативный дефект (Android): в вебе статус-бара нет. На iOS не проявляется (бар прозрачный поверх WebView).

### A9. Затемнение IonModal-шторок не достаёт до статус-бара (Android) — верхняя полоса остаётся яркой
**Приоритет:** nice · **Категория:** layout-stability · **Причина:** stack-config
- **Экран:** все 10 шторок (PaySheet/PriceSheet/…) + MPK-модалы
- **Место:** `src/platform/host/CapacitorHost.ts:96`
- **Что не так:** При открытии шторки оплаты/цен весь экран затемняется backdrop'ом, но полоса статус-бара сверху остаётся ярко-кремовой — в нативных приложениях dim-слой накрывает и статус-бар; здесь视но, что «приложение» кончается ниже него. Техпричина: overlaysWebView:false (capacitor.config.ts:36, CapacitorHost.ts:101) — статус-бар нарисован ОС вне WebView, ion-modal backdrop физически не может его накрыть, а цвет бара при презентации шторок никто не меняет (configureChrome ставит #fdf6ee один раз).
- **Как чинить:** Вариант A (точечный): расширить AgOSHost методом setStatusBarColor и в Sheet.tsx на onWillPresent/onDidDismiss переключать цвет #f6f3ed ↔ затемнённый (например #8f8a83 — фон, умноженный на backdrop-opacity). Вариант B (системный, решает и это, и верхнюю safe-area): перейти на StatusBar.setOverlaysWebView({overlay:true}) + padding-top: env(safe-area-inset-top) из финдинга №1 — тогда backdrop модала сам накрывает зону бара.
- **Нативный риск:** Только Capacitor-Android; в вебе и на iOS (прозрачный бар поверх WebView) backdrop уже визуально доходит до края.

## B. Остальные находки — верификатор понизил, но большинство реальны (64)

Сгруппированы по категории-аудитору. В result-журнале у них сохранены только заголовок и категория
(полная детализация была в транскриптах финдеров). Заголовок описывает суть; маппинг на коды

### Отклик на касание (touch-feedback) — 12
- Главная кнопка всех шторок (.cta) не имеет ни :active, ни :hover — ноль отклика на нажатие
- Чат: все контролы живут только на :hover — на таче фидбек «залипает» после отпускания
- Рынок/Партия: меню действий, аккордеоны, кнопки решения и табы — hover-only, без pressed
- Экран «Кабинет» (профиль): строки, тумблеры и CTA взноса без какого-либо отклика
- Шторка цен: ряды категорий и обе кнопки без pressed-состояния
- Главная: «Моя ферма», шаги «С чего начать» и ask-бар не реагируют на нажатие
- Радио-опции шторок (.big-radio) — выбор способа оплаты без тап-фидбека
- Точки баннера Главной — touch target 6×6px
- user-select/touch-callout не управляются: долгий тап по кнопкам и карточкам выделяет текст
- Формально существующие, но невидимые :active: баннер opacity .96 и чипы решений translateY(.5px)
- «все партии» на Главной: hover-only и тап-таргет ~26px высотой
- Haptics непоследовательны: снятие с продажи, смена цены и отзыв — без вибро при равном весе с отгрузкой

### Переходы и навигация (transitions-navigation) — 12
- go() с dir='back' делает pop вместо открытия экрана: «Обратитесь в TURAN» из партии уводит назад в список
- Системный «назад» внутри визарда не закрывает его: скрытый таб-бар на Главной и «призрачное» переоткрытие визарда
- Push/universal-link deep-link мёртв, пока кабинет открыт: v6 navigate() невидим для v5-острова
- Android аппаратный «назад» на корне таба — мёртвая кнопка: нет backButton-хендлера, свернуть приложение невозможно
- Переключение табов размонтирует уходящий таб: потеря скролла и состояния, нет per-tab стеков
- Скрытие/показ таб-бара — display:none без анимации: скачок высоты контента в момент перехода
- У флоу-страниц (визарды, PubResult) нет exit-анимации — выход резким свапом
- Круговой выход из острова в v6 (членство/регистрация): жёсткий кат + повторный BootScreen на возврате
- Шаги визардов переключаются без какой-либо анимации
- Повторный тап по активному табу не скроллит к началу (native convention не реализована)
- Тап по табу с внутренней страницы оставляет «мёртвую» запись истории — холостое нажатие «назад»
- Кнопка «‹ Главная» в Кабинете лжёт о направлении: возвращает на фактический предыдущий таб

### Загрузка и обновление (loading-refresh) — 14
- Офлайн cold start сбрасывает кабинет активного члена в пустое состояние 'none'
- Офлайн-мутации молча теряются: публикация исчезает, снятие/отгрузка откатываются поллингом
- Pull-to-refresh и любой не-silent refetch подменяют живой контент скелетоном
- Сбой rpc_get_farm_summary показывает вошедшему фермеру демо-ферму («Отёл, день 34», 7 фейковых задач)
- Снятие/отгрузка партии: тост успеха до сервера, состояние не меняется, CTA остаётся нажимаемой
- Ошибка загрузки партий выглядит как «Пока нет ни одной партии»
- Таб «Ферма» — единственный экран данных вообще без механизма обновления
- Подвисший rpc_get_my_context держит BootScreen вечно — ни таймаута, ни ретрая
- Отзыв о покупателе теряется, если уйти с экрана «Спасибо» не через кнопку «К партии»
- Мастер фермы офлайн: тост «Сохранено», а таб «Ферма» показывает «Расскажите, кто у вас в стаде»
- Оплата взноса без pending-состояния: несколько секунд «ничего не произошло», плашка нажимаема повторно
- Скелетон мигает <100мс на быстрой сети; первая загрузка удлинена серийным reviewDue→fetch
- «Опубликовать партию» без прогресс-индикации: реальное сетевое ожидание — до фейкового «поиска»
- Нет рефетча при возврате приложения из фона — до 20-30с устаревших данных после разблокировки

### Стабильность лейаута (layout-stability) — 1
- Toast прибит к bottom:96px — перекрывает CTA/таб-бар, не знает про safe-area и скрытый бар

### Качество движения (motion-quality) — 10
- Таб-бар прячется через display:none — рывок раскладки на каждом переходе
- Дубликат @keyframes mk-pulse — живой статус-дот «торги идут» проигрывает чужую анимацию
- Флоу-страницы (BatchWizard/PubResult/FarmWizard) закрываются мгновенным unmount — есть только present-анимация
- Тост исчезает без анимации — обрыв в один кадр после 2800мс
- Двойной грабер на шторках: родной handle IonModal + свой .sheet-grip/.ps-handle
- OfflineBar появляется/исчезает скачком, сдвигая весь экран
- Шаги визардов сменяются мгновенным свапом — направление движения ничем не объяснено
- Анимируются layout-свойства (left/height/max-height/width) вместо transform — jank на слабых Android WebView
- prefers-reduced-motion уважается лишь частично — бесконечные пульсы/шиммер и Ionic-переходы не гейтятся
- Смена скелетон → контент происходит в один кадр на всех экранах

### Структура и паттерны (structure-patterns) — 15
- Viewport без maximum-scale: iOS авто-зум при фокусе на инпуты <16px и свободный pinch-zoom всего приложения
- Визарды и PubResult невидимы для системного «назад»: аппаратная кнопка/edge-swipe выбрасывает из середины флоу вместо шага назад
- Аппаратный «назад» на корневом табе никогда не сворачивает приложение (Android-конвенция нарушена)
- MkSelect-пикер и CountrySheet — псевдо-шторки: грип без drag-to-dismiss, не закрываются системным «назад», выбиваются из IonModal-рецептуры остальных 10 шторок
- Pull-to-refresh есть только на Главной и Рынке — на «Мои партии» и карточке партии его нет, хотя именно там фермер ждёт обновления сделки
- type="number" на ценовых полях — разрешает e/минус/точку и ломает конвенцию кодовой базы (inputMode=numeric)
- Регистрация: БИН/ИИН (12 цифр) и «Стоимость выезда ₸» открывают полную буквенную клавиатуру — FloatingInput не умеет inputMode
- Док ввода чата (.ai-dock) без env(safe-area-inset-bottom) — на iPhone кнопки mic/send лягут под home-indicator
- Все шрифты — только с fonts.googleapis.com: офлайн в поле и в нативной сборке приложение падает на системные шрифты
- Телефон поддержки TURAN — просто текст, не tel:-ссылка
- Поля первого контакта без автозаполнения: телефон без autocomplete="tel", имя без autocomplete="name"/autocapitalize="words"
- Чат: клавиша Enter отправляет сообщение, но клавиатура показывает «перевод строки» — нет enterkeyhint="send"
- 62 :hover-правила без @media (hover:hover) — «залипшая» подсветка строк и карточек после тапа на тач-устройствах
- document.title статичен — все экраны кабинета называются «AgOS — TURAN»
- Кастомные контролы без state-семантики: тумблер без role=switch, чек/радио без aria-checked, CTA-span без клавиатурного обработчика
