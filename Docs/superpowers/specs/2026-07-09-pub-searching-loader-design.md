# Экран «Ищем покупателя» между публикацией и результатом (TSP-1)

**Дата:** 2026-07-09
**Домен:** UI / Farmer cabinet / TSP-1 (визард «Продать новую партию»)
**Ветка:** claude/farmer-batch-loader-state-f82c12

## Проблема

После публикации партии `handlePublish` ([BatchWizard.tsx:81](../../../src/pages/cabinet/shell/tsp/wizard/BatchWizard.tsx)) синхронно вызывает
`rpc_create_batch` + `rpc_self_auto_match_batch`, вычисляет вариант результата (A/B/C/D)
и сразу вызывает `onDone` → `PubResult`. Вариант **A «Покупатель найден»** выскакивает
мгновенно — фермер не понимает, что система искала покупателя, и «мгновенный» результат
читается как глюк, а не как исход поиска.

Ключевой факт: к моменту показа результата **вся работа уже сделана** (автоматч отработал
синхронно). Значит нужен не реальный лоадер асинхронной задачи, а **выдержанная пауза-поиск**
(минимальное время показа), чтобы «нашёл сразу» ощущался как результат.

## Решение

Внутренняя фаза `searching → done` внутри существующего `PubResult.tsx`. Аддитивно, один файл;
`CabinetApp.tsx` и `BatchWizard.tsx` НЕ трогаются.

### Поведение

- `PubResult` получает `phase` во внутреннем `useState`.
- Варианты **A/B/C**: стартуют в `searching` → `useEffect`-таймер **~2.2 c** → `done`.
- Вариант **D** (запланировано): поиска нет → стартует сразу в `done` (текущее поведение).
- Фаза `searching`: блок `.mk-loader` (спиннер `.mk-spin`) + сменяющиеся **3 фразы**:
  1. «Ищем покупателя для вашей партии…»
  2. «Сверяем цену с активными заказами…»
  3. «Проверяем покупателей в вашем районе…»
  Смена ~ каждые 733 мс (2200/3). Футер `.sh-foot` скрыт (нечего нажимать).
- Фаза `done`: текущий `PubResult` без изменений (варианты A/B/C/D).

### Переиспользуемые стили ДС (новых не добавляем)

- `.mk-loader` + `.mk-spin` — тот же лоадер, что в шаге 3 «Определяем категорию…»
  ([market-proto.css:171](../../../src/pages/cabinet/shell/market-proto.css))
- `.mk` / `.phone-scroll` — контейнер экрана
- `PhIcon`, палитра, `@keyframes mk-spin`
- `prefers-reduced-motion` уже уважается в ДС

### Что сохраняется (HS-2 / HS-5, аддитивно)

- Логика публикации, автоматча, вычисления варианта, `onDone`, `addBatch`, haptics — не тронуты.
- Тела вариантов A/B/C/D в `PubResult` — не тронуты.
- Контракт props `PubResult` — не меняется.
