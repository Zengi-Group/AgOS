## 0. Дизайн-рамка

**Язык — язык shell, без изобретений.** Мастер обязан читаться как родной брат TSP-визарда:
тот же каркас `mk-wiz-bar` + прогресс + `mk-h1`-вопрос + док-футер `sh-foot`, те же контролы
(`StepperCtl`, `BigRadio`, чипы `mk-fat-c`), тёплая палитра `:root` фермера, иконки только
Phosphor через `PhIcon`.

**Три собственных дизайн-хода слайса** (то, чем мастер отличается от анкеты):

1. **Payoff — не шаг, а награда.** Экран цен (Payoff-1) и экран финала не имеют прогресс-бара
   и «Назад» — только выход. Визуально это «выдох» между ярусами, а не пункт анкеты.
2. **«Зачем спрашиваем» под каждым вопросом яруса «План»** — строка-контракт честности
   (критерий F-D14 «каждый вопрос виден в результате» становится видимым элементом UI).
3. **Цены отсортированы по стаду фермера.** Payoff-1 показывает карточки только ЕГО категорий,
   с бейджем «у вас N голов», по убыванию поголовья. Остальные категории — одна ссылка в
   существующую шторку PriceSheet (reuse, не дубль).

Чего НЕ делаем: конфетти/эмодзи, произвольные иконки на каждую категорию скота (в PhIcon их
нет — не рисуем руками, memory: icons-phosphor-only), оценку стада в тенге (веса не
спрашиваем — считать «млн ₸» не из чего, честность важнее вау).


## 2. Флоу-карта (step-map v2.1 → экраны)

```
SCR-F1 Состав стада ──────────► SCR-F2 Payoff-1 · Цены ──[X/«Пока хватит»]──► выход (F0b)
      (ярус 1 · 1 вопрос)              │
                                       │ CTA-мост: «Ещё N вопросов — план работ на год»
                                       ▼
        выведен cow_calf/combined:   SCR-F3 Отёл (+месяц) → SCR-F4 Молодняк → SCR-F5 Содержание
        выведен finishing:           SCR-F5 Содержание                        (N=1, мост «Ещё 1 вопрос»)
        телята>0, маточное=0:        SCR-F4 Молодняк → SCR-F5 Содержание      (N=2)
                                       │
                                       ▼
                     порог достигнут:  SCR-F6 Генерация (loader) → план создан? F8 : F7
                     план создан:      SCR-F8 Финал «План готов» → CTA «Посмотреть план» → выход (state C)
                     ниже порога:      SCR-F7 Финал «Стадо записано» → выход (F0b)
```

Ветвление, вывод архетипа, порог — логика Узла 1 §5 (не дублируем). Дизайну важно одно:
**состав яруса «План» известен уже на Payoff-1** (архетип выведен после F1), поэтому мост
называет точное число вопросов, а прогресс яруса 2 честный с первого экрана.

## 3. Прогресс-модель и шапка мастера

Ярусная модель (двух «анкет», разделённых наградой):

| Экран | Шапка |
|---|---|
| F1 (ярус 1) | `mk-wiz-bar`: ← назад (=выход на F0) · **без прогресс-точек** · X. Подпись `mk-wiz-step`: `вопрос 1 · стадо` |
| F2 Payoff-1 | **без wiz-bar.** Только X (`.mk-wiz-exit`) в правом верхнем углу |
| F3–F5 (ярус 2) | `mk-wiz-bar`: ← · `WizProgress` из N точек ветки · X. Подпись: `вопрос k из N · <тема>` |
| F6 loader | ничего (полноэкранный `mk-loader`) |
| F7 финал | без wiz-bar (паттерн PubResult) |

`WizProgress` параметризуется числом точек (новый проп `count`, default 5 — TSP не трогаем,
аддитивно HS-5). Один вопрос яруса (finishing) → точки не показываем (1 точка = шум),
остаётся только подпись `вопрос 1 из 1 · содержание`.

Под CTA каждого шага — `DraftNote`-строка: `сохраняется после каждого ответа`.

### SCR-F6 · Генерация плана (порог достигнут)

Полноэкранный `mk-loader` (паттерн PubResult.searching, ~2200 мс, ротация фраз):
`Собираем план под ваше стадо…` → `Расставляем работы по месяцам…` →
`Сверяем с вет-календарём…`. Хэндофф (ARS-215): `onGenerate(): Promise<boolean>` —
финал не раньше лоадера и не раньше ответа генерации (хард-кап 10 с → F7);
`generated:true` → SCR-F8, иначе → SCR-F7.

### SCR-F8 · Финал «план готов» (ARS-215, payoff Узла 1)

«Ферма» = state C; один путь вперёд, R-14 — link «Ответить сейчас» здесь не показываем).

### State C · Таб «Ферма» · План есть (ARS-215)

## 10. Решения дизайна

- **D-FW-1 · Ярусная прогресс-модель.** Payoff-экраны вне прогресса; ярус 2 нумеруется
  заново («вопрос k из N»), N — по выведенной ветке. Альтернатива (сквозные 5 точек)
  отвергнута: ломает обещание моста «ещё 3 вопроса» и делает выход на Payoff-1 похожим
  на «бросил на середине».
- **D-FW-2 · Без оценки стада в ₸ на Payoff-1.** herdValueMln требует средних весов — их
  не спрашиваем (Узел 1 §4). Показ выдуманных весов = ложь в первом же payoff. Вернуть
  оценку можно, когда веса появятся из TSP-касаний.
- **D-FW-3 · CTA-иерархия Payoff-1:** primary = мост к плану (стратегическая цель — лестница
  вовлечения), «Продать через TURAN» — вторичная кнопка на карточке категории, выход —
  третичный link. Продажа не primary: гейт членства сделал бы главную кнопку экрана
  недоступной половине аудитории.
- **D-FW-4 · Пауза-ритуал перед ценами (900 мс)** — паттерн PubResult: награда читается как
  результат работы системы, не как мгновенная смена формы. Короче, чем у публикации (2200):
  здесь нет реального поиска.
- **D-FW-5 · Финал без плана (F7) — тоже награда,** а не отказ: зелёный checkCircle,
  «стадо записано», путь назад к вопросам — link, не guilt-trip.
